# 测评与技能树系统交接文档 (阶段二)

## 1. 概述
在阶段二的开发中，我们完成了知识图谱（技能树）的深化，实现了岗位模型的构建，以及基于岗职双维的测评系统。该系统允许用户进行岗位相关的技能测试，并自动计算用户的技能掌握度及岗位适配度（匹配度）。

## 2. 数据库更新设计
更新了数据库初始化脚本 `docs/database/init.sql`，主要调整和新增了以下核心表：
- `knowledge_graphs` (技能树): 扩展了 `parent_id` 以支持层级结构。
- `job_positions` (岗位): 存储岗位基本信息（级别、行业等）。
- `job_skills` (岗位-技能关联): 岗位与所需核心技能的多对多映射表，带有 `weight`（权重）字段。
- `assessments` (测评试卷) & `questions` (测评题目): 试卷及其包含的题目，题目关联到具体的知识图谱节点（技能点）。
- `user_assessment_records` (测评记录): 记录用户每次提交测评的整体得分和答题详情 JSON。
- `user_skill_mastery` (用户技能掌握度): 记录用户在各个知识图谱节点上的当前掌握度（百分比），基于历次测评得分动态计算（目前采用简单移动平均）。

## 3. 核心功能实现
### 3.1 岗位与技能树管理
- **API 路由**: `src/api/v1/job.py`
- **主要接口**:
  - `POST /api/v1/jobs`: 创建岗位并绑定所需技能节点。
  - `GET /api/v1/jobs`: 分页获取岗位列表。
  - `GET /api/v1/jobs/{job_id}/skill-tree`: **核心接口**，返回一棵完整的知识树，并根据所选岗位在树节点中标记 `is_required` (该节点为必选) 和 `has_required_child` (该节点的子节点包含必选)，方便前端渲染带高亮的技能树。

### 3.2 测评系统与岗位适配度模型
- **API 路由**: `src/api/v1/assessment.py` 和 `src/api/v1/job.py`
- **主要接口**:
  - `POST /api/v1/assessments`: 创建包含题目的试卷。
  - `POST /api/v1/assessments/submit`: 用户提交试卷。
    - **逻辑说明**: 后端会遍历提交的答案，对单选/多选题进行自动判卷计算得分。同时，会将每道题的得分按其绑定的技能节点进行汇总。最后，将本次测评的技能得分更新到 `user_skill_mastery` 表中（新得分与历史得分求平均，表示最新的掌握水平）。
  - `GET /api/v1/jobs/{job_id}/match`: 计算岗位匹配度。
    - **逻辑说明**: 查询目标岗位需要的所有技能，然后对比当前用户在 `user_skill_mastery` 表中对应技能的掌握度，计算出一个平均的百分比得分（0-100%）。

## 4. 技术与规范说明
- **模型设计坑点防范**: 在 `KnowledgeGraph` 的自引用关系 `children` 中，由于 SQLAlchemy 的限制，去掉了 `cascade="all, delete-orphan"`，改为仅依赖外键的 `ON DELETE SET NULL` 行为，以防止多对一关系引发 `ArgumentError`。
- **全局异常优化**: 对 `RequestValidationError` 进行了专门拦截，并使用自定义序列化将字节类型安全地转换为字符串，以防抛出 JSON 序列化异常（已在 `exceptions.py` 中修复）。
- **单元测试**: 编写了 `test_job_and_assessment` 综合流程测试，涵盖了“创建技能->创建岗位->获取高亮技能树->创建试卷->提交答卷得分->计算最终岗位匹配度 100%”的全链路断言，执行成功。

## 5. 后续待优化项
- 问答题（Text类型）的主观题自动判卷，需要在后续阶段（阶段四）接入 LLM 进行智能打分。
- 岗位匹配度的计算逻辑目前是简单的未加权平均，未来可利用 `job_skills.weight` 字段实现更科学的加权算法。
