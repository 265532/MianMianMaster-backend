### 1.2 优先级矩阵

| 优先级       | 定义          | 响应时间  | 示例               |
| --------- | ----------- | ----- | ---------------- |
| **P0-致命** | 安全漏洞/数据丢失风险 | 24h 内 | CORS 全开、JWT 永不过期 |
| **P1-严重** | 核心功能缺陷/合规问题 | 1周内   | 权限绕过、测试覆盖不足      |
| **P2-重要** | 性能瓶颈/体验问题   | 2-4周  | 异步任务缺失、缓存优化      |
| **P3-一般** | 代码质量/可维护性   | 按计划   | 格式化、文档补充         |

## 二、轨道 A: 安全加固计划 (Week 1-2)

### 2.1 P0 任务清单 — 必须立即完成

#### Task A1: CORS 安全配置修复

- **优先级**: 🔴 P0
- **预估工时**: 0.5 天
- **负责人**: 后端开发
- **交付物**:
  - [ ] 新增 `ALLOWED_ORIGINS` 配置项到 `config.py`
  - [ ] 修改 `main.py` CORS 中间件，从环境变量读取白名单
  - [ ] 更新 `.env.example` 模板
  - [ ] 编写跨域测试用例
- **验收标准**: 非白名单来源请求返回 403

#### Task A2: JWT 双 Token 机制实现

- **优先级**: 🔴 P0
- **预估工时**: 2 天
- **负责人**: 后端开发
- **交付物**:
  - [ ] Access Token 有效期改为 30 分钟
  - [ ] 新增 Refresh Token (有效期7天，存储 Redis)
  - [ ] 实现 `/auth/refresh` 接口
  - [ ] 实现 Token 黑名单机制 (登出时加入)
  - [ ] 更新 `security.py` Token 创建逻辑
  - [ ] 更新前端对接文档
- **验收标准**: Access Token 过期后可通过 Refresh Token 续期

#### Task A3: RBAC 权限逻辑清理

- **优先级**: 🔴 P0
- **预估工时**: 1 天
- **负责人**: 后端开发
- **交付物**:
  - [ ] 移除 `deps.py` 中 `username == "admin"` 硬编码判断
  - [ ] 统一使用角色名称判断 (`has_admin_role`)
  - [ ] 新增超级管理员角色常量 `SUPER_ADMIN_ROLE = "admin"`
  - [ ] 补充权限检查单元测试
  - [ ] 更新交接文档
- **验收标准**: 所有权限判断基于角色，无用户名硬编码

#### Task A4: 移除生产环境自动建表

- **优先级**: 🔴 P0
- **预估工时**: 0.5 天
- **负责人**: 后端开发 + DevOps
- **交付物**:
  - [ ] 条件化移除 `Base.metadata.create_all()` (仅开发环境保留)
  - [ ] 新增 `ENVIRONMENT` 配置项 (development/production)
  - [ ] Dockerfile 启动命令增加 `alembic upgrade head`
  - [ ] 编写数据库初始化部署文档
- **验收标准**: 生产环境启动不自动创建表结构
