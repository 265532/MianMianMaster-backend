### 2.2 安全性审查 (评分: 58) — 🔴 关键问题

#### 🔴 严重安全问题

##### 问题 1: CORS 配置过于宽松
**位置**: [main.py:34-40](../../src/main.py#L34-L40)
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],  # ❌ 允许所有来源
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```
**风险**: 跨站请求伪造(CSRF)、敏感数据泄露  
**修复方案**: 
```python
allow_origins=settings.ALLOWED_ORIGINS  # 从环境变量读取白名单
```

##### 问题 2: JWT Token 有效期过长
**位置**: [config.py:12](../../src/core/config.py#L12)
```python
ACCESS_TOKEN_EXPIRE_MINUTES: int = 60 * 24 * 8  # 8天 = 11520分钟
```
**风险**: Token 泄露后长期有效，无法及时撤销  
**修复方案**: 
- Access Token: 30分钟 ~ 2小时
- Refresh Token: 7天 (存储在 Redis，可随时撤销)
- 实现 Token 黑名单机制

##### 问题 3: Admin 用户名硬编码绕过权限
**位置**: [deps.py:87-92](../../src/api/deps.py#L87-L92)
```python
if required_perm not in perms and "all:all" not in perms and current_user.username != "admin":
    has_admin_role = any(r.name == 'admin' for r in current_user.roles)
```
**风险**: 权限绕过逻辑混乱，基于用户名而非角色判断  
**修复方案**: 统一使用角色判断，移除 username 硬编码

##### 问题 4: 密码重置 Token 未限制使用次数
**位置**: [auth_service.py:134-158](../../src/services/auth_service.py#L134-L158)
**风险**: 同一 Token 可被多次使用  
**修复方案**: 在数据库记录 Token 使用状态或使用一次性 Token

#### ⚠️ 中等安全风险

| 问题 | 位置 | 风险描述 | 建议 |
|------|------|---------|------|
| SMS 验证码明文存储 | [user.py:83](../../src/models/user.py#L83) | 数据库泄露则验证码暴露 | 存储哈希值而非原文 |
| 缺少登录失败锁定机制 | [auth_service.py](../../src/services/auth_service.py) | 暴力破解风险 | 实现 5次失败锁定15分钟 |
| 缺少 CSRF 保护 | 全局 | 表单提交场景风险 | 使用 SameSite Cookie 或 CSRF Token |
| 敏感信息未脱敏输出 | User Schema | API 响应可能包含手机号 | 手机号脱敏显示 (138****8000) |
| .env 文件缺失 | 根目录 | 可能使用默认配置 | 创建 `.env.example` 模板 |
| SECRET_KEY 默认值 | [config.py:12](../../src/core/config.py#L12) | 无默认值会导致启动失败 | 添加生成提示或启动时验证强度 |

#### ✅ 安全亮点

- ✅ 密码使用 bcrypt 加密 ([security.py](../../src/core/security.py))
- ✅ 密码复杂度验证 (8位+大小写+数字+特殊字符)
- ✅ JWT 使用 HS256 算法签名
- ✅ API 限流机制 (slowapi)
- ✅ SQL 注入防护 (SQLAlchemy ORM 参数化查询)
- ✅ 日志脱敏过滤器 ([logger.py](../../src/core/logger.py))
